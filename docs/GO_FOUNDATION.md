# GO foundation / catalog increment — 2026-10-17

## Implemented locally, not deployed

- Same passenger Flutter app and existing backend. GO home has Taxi / Parcel delivery / Food / Market, a light yellow/black layout, responsive cards and shared Profile / Orders navigation. Parcel service explicitly shows its incomplete integration; no fake parcel booking is offered.
- Existing taxi form and active Ride stay mounted in IndexedStacks. Returning home or browsing shopping does not clear the trip. Shared cards, addresses, promos, support and settings are reached through existing widgets/callbacks. The profile keeps the original account, avatar/settings and bonus balance; no second wallet or authentication store exists. The old taxi history implementation is retained but its duplicate shell navigation is replaced by GO history.
- GO active/history panels read actual existing `/api/orders/current`, `/api/orders/history`, and owned `/api/delivery/customer/orders`. A shopping order's `transport_order_id` removes its duplicate TM ride. Legacy purchases remain labelled purchases, not parcels. Cached status remains visible on partial connection failure with an error notice. Completed taxi/purchase rows are excluded from active panels; background polling stops when inactive/paused.
- Shared history filters All / Taxi / Parcel / Food / Market and opens existing ride details or owned shopping details. History presentation is an initial read-only integration; richer timestamps, service typing for legacy TM parcel rides, support links and complete final styling remain.
- Schema6 adds nullable explicit store `service_kind` (`food`/`market`). Old stores are not guessed from names/category translations. Admin must choose the mapping. Catalog/category/search/product detail queries filter on server data, and responses explicitly acknowledge the service. New clients reject an older backend that ignores the filter. Older API updates omit, rather than erase, existing mapping; new order snapshots preserve classification.
- GO-classified stores **cannot use the old checkout/ledger flow**: domain/HTTP gates reject quotes and even older unconsumed quotes after store mapping. No stock/order write succeeds through that path. Client checkout is also disabled with an explicit explanation. Legacy historical orders/partner terms are preserved. Admin's old partner commission is shown read-only, not presented as TM commission; new form defaults create no partner fee.
- Schema7 stores up to10 ordered manual recommendations per product. Saving product and recommendation choices is atomic under existing stock-version checks. Same-store ownership, self-reference/duplicate/limit validation and stale-edit rejection are enforced server-side. Public detail responses exclude hidden/out-of-stock/foreign products. No AI or fake popular products are added.
- Partner/admin product editor supports own-catalog search, add/remove/up/down ordering. Product details in the app show server description/photo/price and recommendations, and add them to the existing one-store cart. Variants, weights/composition, promotions and the final two-column visual layout still need subsequent work.
- Two existing Material background/ink issues in Settings and Cards were exposed by the integrated shell test and corrected with Material card surfaces; account/payment behavior unchanged.
